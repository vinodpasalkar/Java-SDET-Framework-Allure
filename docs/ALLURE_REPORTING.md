# Allure reporting guide

## What is included

- Cucumber 7 Allure adapter writes scenario and step results to `target/allure-results`.
- Cucumber HTML and JSON reports remain available under `target/cucumber-reports`.
- Failed Cucumber scenarios capture a browser screenshot before the driver is closed; the image is attached to the scenario and appears in Allure.
- The Allure JUnit 5 adapter is included for JUnit 5 tests such as the REST Assured API test.
- GitHub Actions uploads `target/allure-results` and the Cucumber reports even when tests fail.

## Run locally

1. Run the suite: `mvn clean test`.
2. Install the Allure command-line tool for your operating system. Follow the official instructions at https://allurereport.org/docs/install/.
3. Open a live report: `allure serve target/allure-results`.
4. Or create a static report: `allure generate target/allure-results --clean -o target/allure-report`.
5. Open `target/allure-report/index.html` in a browser.

The Allure CLI is a separate local tool; the Maven test run creates the result data but does not itself open a report window.

## CI usage

The GitHub Actions workflow stores `allure-results` and `cucumber-reports` as a downloadable build artifact. Download the artifact and run `allure serve allure-results` locally to inspect it. The workflow does not publish a public report site.

## Important notes

- A screenshot is attached only for a failed Cucumber scenario and only when a WebDriver session exists.
- The existing API test is a JUnit 5 test. Its Allure adapter is present; to enrich API output further, add Allure annotations such as `@Epic`, `@Feature`, `@Story` and `@Step` where useful.
- Results are regenerated by `mvn clean test`; `clean` removes previous result files so reports do not mix old and new executions.
